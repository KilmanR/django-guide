Docker для Django (основные понятия и команды)

Docker обёртывает приложение в контейнер — изолированное окружение, где уже есть
Python, библиотеки и запуск команд. Так проект живёт одинаково на любом компьютере.

Ключевые понятия (коротко)

ТерминЧто это
-----------------
Образ (image)«чертёж»/пакет со всем нужным (Python + Django + код). Неизменяем.
Контейнер (container)запущенный образ — живой процесс (сами запускаете/останавливаете).
Dockerfileфайл-инструкция, из которого строится образ.
docker-composeмного контейнеров сразу (у нас web + база postgres) одной командой.
Docker Hub / registryонлайн-хранилище готовых образов (postgres:16, python:3.12).

Dockerfile (как строится образ)

FROM python:3.12-slim        # база-образ (свежий Python)
WORKDIR /app                 # рабочая папка внутри контейнера
COPY . /app                  # копируем код
RUN pip install -r requirements.txt   # ставим зависимости
CMD ["python", "manage.py", "runserver"]  # команда старта

Основные команды Docker

docker build -t myapp .       # собрать образ из Dockerfile
docker images                 # список образов
docker run -it myapp          # запустить контейнер в фореграунде

docker ps                     # запущенные контейнеры
docker ps -a                  # все (включая остановленные)

docker stop <id>              # остановить
docker rm <id>                # удалить контейнер
docker exec -it <id> bash     # зайти внутрь запущенного контейнера
docker logs <id>              # логи контейнера
docker rmi <образ>            # удалить образ

Docker Compose (наше: web + db)

Файл docker-compose.yml описывает все сервисы и связи одной командой.

services:
  db:
    image: postgres:16-alpine
    environment:
      POSTGRES_USER: django
      POSTGRES_PASSWORD: django
      POSTGRES_DB: mydb
  web:
    build: .                 # собирается из Dockerfile
    ports:
      - "8000:8000"          # порт наружу : порт внутри
    volumes:
      - ./app:/app           # код с диска внутрь (правки сразу видны)
    depends_on:
      - db
docker compose up -d        # запустить всё (в фоне)
docker compose ps           # статус сервисов
docker compose logs -f web  # смотреть логи (f = follow)
docker compose down         # остановить и убрать контейнеры (данные в volume остаются)
docker compose build        # пересобрать образ после изменений

Важные детали для Django

  • Порты: ПОРТ_СНАРУЖИ:ПОРТ_ВНУТРИ. Внутри Django слушает 0.0.0.0:8000,

снаружи доступен на том же 8000. 0.0.0.0 = слушать для всех адресов.
- Volumes: синхронизируют папку с кодом между диском и контейнером. Изменили
код → перезапустить runserver (или он сам рестартует с --reload).
- Переменные окружения: подключение к БД в контейнере передаётся env-переменными
(хост БД = имя сервиса db, а не localhost!).
- База в контейнере: данные хранятся в volume pgdata — переживают down.
Чтобы полностью сбросить БД: docker compose down -v (удалит данные!).

Типичный цикл работы (по шагам, как мы делали)

docker compose up -d          # подняли Django + Postgres
docker compose exec web python manage.py startapp polls   # добавили приложение
# ... отредактировали код в ./app ...
docker compose logs -f web    # смотрим ошибки запуска

Class-Based Views (CBV) — вглубь

FNV — функции, CBV — классы. CBV удобны для типовых сценариев: список, деталь,
создание/редактирование/удаление, формы.

Базовые атрибуты

from django.views.generic import ListView

class BookListView(ListView):
    model = Book                    # достаточный минимум
    template_name = 'app/books.html'      # по умолчанию: 'app/book_list.html'
    context_object_name = 'books'         # переменная в шаблоне (по умолч. object_list)
    paginate_by = 10                      # пагинация

ListView — детали

class BookListView(ListView):
    model = Book
    template_name = 'app/books.html'
    context_object_name = 'books'

    def get_queryset(self):          # переопределить выборку
        qs = super().get_queryset()
        return qs.filter(author__isnull=False).order_by('title')

    def get_context_data(self, **kwargs):   # добавить в контекст
        ctx = super().get_context_data(**kwargs)
        ctx['total'] = Book.objects.count()
        return ctx

DetailView — детальная страница

# urls.py
path('book/<int:pk>/', views.BookDetailView.as_view(), name='book_detail'),
# или <slug:slug>

class BookDetailView(generic.DetailView):
    model = Book
    template_name = 'app/book_detail.html'
    context_object_name = 'book'
    # автоподстановка. Если pk не тот — django возбуждает Http404

FormView — форма (без сохранения, для действий)

class ContactView(generic.FormView):
    template_name = 'app/contact.html'
    form_class = ContactForm
    success_url = '/thanks/'

    def form_valid(self, form):      # вызывает SuccessOnlyMixin
        form.send_email()            # свои действия с данными
        return super().form_valid(form)
        # не возвращайте HttpResponse без super() — потеряете flow

CreateView / UpdateView

class BookCreate(generic.CreateView):
    model = Book
    fields = ['title', 'author', 'price']
    template_name_suffix = '_form'        # app/book_form.html
    success_url = reverse_lazy('books:list')   # reverse_lazy — на этапе класса

class BookUpdate(generic.UpdateView):
    model = Book
    fields = ['title', 'price']
    template_name_suffix = '_form'
    success_url = reverse_lazy('books:list')
  • fields обязателен (или form_class).
  • форма выводится как {{ form }} в шаблоне.
  • для CreateView пишете form_valid — получаете instance.

DeleteView + подтверждение

class BookDelete(generic.DeleteView):
    model = Book
    template_name_suffix = '_confirm_delete'   # app/book_confirm_delete.html
    success_url = reverse_lazy('books:list')

В шаблоне _confirm_delete — объект object и форма {{ form }}.
Безопасно: нужен только POST-запрос (кнопка submit внутри формы).

Mixins — переиспользование логики

from django.contrib.auth.mixins import LoginRequiredMixin, UserPassesTestMixin

class StaffRequired(LoginRequiredMixin, UserPassesTestMixin):
    login_url = '/accounts/login/'
    raise_exception = True            # вместо редиректа — 403

    def test_func(self):
        return self.request.user.is_staff

class BookEdit(StaffRequired, generic.UpdateView):
    model = Book
    fields = ['title', 'price']
    success_url = reverse_lazy('books:list')

Порядок: защиты сверху, generic.* внизу (не разбиваете Mixin-ы в разные места).

Ещё полезные штуки

  • TemplateResponseMixin — рендерит шаблон в render_to_response.
  • ContextMixin — собирает контекст (get_context_data).
  • MultipleObjectMixin, SingleObjectMixin — логика списка/объекта.
  • CBV можно настраивать и без наследования: as_view(template_name='x.html').

Что стоит запомнить

  • reverse_lazy (не reverse) — URL нужен только при вызове .as_view().
  • template_name_suffix:

- Форм-суффиксы: _form, _confirm_delete, _update, _create.
- get_object() для DetailView — если нужен объект сразу (в get_context_data).
- Не вызывайте super().get() напрямую без причины — flow CBV строгий.

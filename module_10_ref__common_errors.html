Частые ошибки в Django: топ-10 и их расшифровка

Ошибки Django бывают пугающими по форме, но почти всегда — привычными по сути.
Здесь — «частотная десятка»: как выглядит traceback, что реально происходит
и что делать. Ищите свою ошибку по названию исключения.

1. TemplateDoesNotExist

django.template.exceptions.TemplateDoesNotExist: blog/post_detail.html

Что произошло: Django не нашёл шаблон по переданному имени.

Почему бывает:
- опечатка в имени файла или пути;
- шаблон создан не там, где Django ищет (не в папке templates приложения, а рядом);
- не отрестартовал develop-сервер после создания файла;
- в render(request, "...") передан путь без ведущего app/.

Что делать:

python manage.py check   # проверит структуру

Убедитесь, что файл лежит в app/templates/app/post_detail.html и имена совпадают
с точностью до символа.

2. NoReverseMatch

django.urls.exceptions.NoReverseMatch: Reverse for 'post_detail' not found.
'post_detail' is not a valid view function or pattern name.

Что произошло: вы написали {% url 'post_detail' ... %} (или reverse(...)) —
а URL с таким именем не существует.

Почему бывает:
- name= не указан в path() — urlpattern не зарегистрирован под именем;
- опечатка в имени;
- URL живёт в другом приложении, и вы забыли app_name / пространство имён;
- в {% url %} переданы неправильные аргументы (не хватает pk и т.д.).

Что делать: открыть urls.py, найти path(... name='...'). Имя в шаблоне должно
совпадать. Ошибка почти всегда «имя или аргументы не те».

3. OperationalError: no such table

sqlite3.OperationalError: no such table: blog_post

Что произошло: Django обращается к таблице, которой нет в базе.

Почему бывает:
- миграции не применены: python manage.py makemigrations и migrate;
- создали модель после того как сайт запущен — таблица появится только после migrate;
- начинали проект на другой базе (напр., тестовая) и переключились.

Что делать:

python manage.py makemigrations
python manage.py migrate
python manage.py showmigrations   # посмотреть, что не применено

4. DisallowedHost

DisallowedHost: Invalid HTTP_HOST header: 'myapp.herokuapp.com'.
You may need to add 'myapp.herokuapp.com' to ALLOWED_HOSTS.

Что произошло: Django отклоняет запрос — Host-заголовок не в ALLOWED_HOSTS.

Почему бывает: на новом домене/порту забыли список. Баг-фича: это защита от подделки
Host-заголовка.

Что делать: добавить свой домен в ALLOWED_HOSTS = ["mydomain.ru"] (не заводите туда
* на проде). В разработке можно ["localhost", "127.0.0.1"].

5. KeyError при обращении к request.POST

KeyError: 'title'

Что произошло: обращаетесь к полю формы как request.POST['title'], а его нет.

Что делать: почти всегда лучше работать через форму: form = MyForm(request.POST),
form.is_valid(), form.cleaned_data['title']. request.POST даёт KeyError для
отсутствующего ключа — несовпадение имён в HTML и view.

6. AttributeError: 'NoneType' object has no attribute ...

AttributeError: 'NoneType' object has no attribute 'title'

Что произошло: переменная None, а вы пытаетесь взять у неё поле.

Почему бывает:
- get() вернул ничего → post = Post.objects.get(...) упал на DoesNotExist, если
запись отсутствует — но если повезло один раз и записи нет, код идёт дальше как будто
объект есть;
- request.user не авторизован и is_authenticated в коде не проверен.

Что делать:

post = Post.objects.filter(pk=pk).first()   # None вместо исключения
if post is None:
    raise Http404("Пост не найден")

Для request.user используйте request.user.is_authenticated до обращения к полям.

7. RelatedObjectDoesNotExist / DoesNotExist

RelatedObjectDoesNotExist: User has no profile.

Что произошло: OneToOne обращение к несуществующей записи: user.profile.avatar
без проверки, есть ли профиль.

Что делать:

profile = getattr(user, "profile", None)
# или
try:
    profile = user.profile
except Profile.DoesNotExist:
    profile = None

8. ValueError: Cannot query "..." Must be an instance of ...

ValueError: Cannot query "Blog": Must be "Blog" instance.

Что произошло: фильтруете по полю, передав не объект модели, а его имя/строку/id
неправильно: Post.objects.filter(blog=blog_id) вместо blog=blog_instance.

Что делать: передавайте объект:

blog = Blog.objects.get(pk=blog_id)
Post.objects.filter(blog=blog)

9. FieldError: Cannot resolve keyword

FieldError: Cannot resolve keyword 'creteated' into field. Choices are: ...

Что произошло: опечатка в имени поля в filter/values/order_by.

Что делать: сообщение перечисляет доступные поля — сверьтесь с моделью.

10. CSRF verification failed

CSRF verification failed. Request aborted.

Что произошло: POST без корректного CSRF-токена.

Почему бывает:
- в HTML <form> нет {% csrf_token %};
- AJAX-запрос без токена;
- (не частый случай) включён CSRF_USE_SESSIONS и SessionMiddleware не в списке.

Что делать: вставить {% csrf_token %} внутрь формы. Для AJAX — передавать токен
в заголовке X-CSRFToken (подробно — «Формы и безопасность» в документации).
@csrf_exempt на view — почти всегда признак того, что вы обходите защиту, а не красиво её
решаете.

Ещё быстрые подсказки

ОшибкаСмысл
ImproperlyConfiguredчто-то с настройками — читаем текст до двоеточия
MigrationSchemaMissing«миграции не синхронизированы» → migrate
StaticFilesStorage Warningне собран collectstatic
MEDIA_URL в шаблоне на пустом местене подали request через render с запросом
RuntimeWarning: received signal SIGINTне ошибка кода, а пойманный Ctrl+C

Почти все ошибки решаются по одному паттерну: прочитайте имя исключения как подсказку,
проверьте миграции (migrate), имя шаблона, имя URL и передаваемые аргументы формы.
Если непонятно — python manage.py shell и пощёлкайте там шаг за шагом: видно на своих
данных.

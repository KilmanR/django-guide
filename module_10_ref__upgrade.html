Что изменилось с Django 2.x: шпаргалка обновления

Туториалы MDN и официальный текст написаны на Django 2.x, а актуальный релиз — 6.x.
Большинство примеров там работает и сейчас (модели, ORM, формы, админка), но синтаксис
некоторых строк изменился. Эта страница — быстрая памятка: встретили ошибку в старом
примере — нашли строку здесь, переписали, поехали дальше.

Самое главное — маршруты

В Django 2.x и раньше URL писали через регулярные выражения и url():

# Было (Django 1.x–3.x)
from django.urls import url
urlpatterns = [
    url(r'^posts/$', views.post_list, name='post_list'),
    url(r'^posts/(?P<pk>\d+)/$', views.post_detail, name='post_detail'),
]

С Django 3.1 url() стал устаревшим, с Django 4.0 — удалён. Сейчас — path():

# Стало (Django 3.1+)
from django.urls import path
urlpatterns = [
    path('posts/', views.post_list, name='post_list'),
    path('posts/<int:pk>/', views.post_detail, name='post_detail'),
]
Регулярка (url)Эквивалент в path()
(?P<pk>\d+)<int:pk>
(?P<slug>[\w-]+)<slug:slug>
(?P<username>\w+)<str:username>
\d{4}/<int:year>

Регулярные выражения всё ещё возможны через re_path — но они нужны в редких случаях:

from django.urls import re_path
re_path(r'^posts/(?P<pk>\d+)/$', views.post_detail),

В шаблонах стало одинаково: {% url 'post_detail' pk=post.pk %} — не изменилось.

Настройки, которые меняются при переносе старого проекта

1. MIDDLEWARE_CLASSES → MIDDLEWARE

В старых текстах встречается кортеж MIDDLEWARE_CLASSES. Это удалено. Используйте список:

MIDDLEWARE = [
    "django.middleware.security.SecurityMiddleware",
    "django.contrib.sessions.middleware.SessionMiddleware",
    "django.middleware.common.CommonMiddleware",
    "django.middleware.csrf.CsrfViewMiddleware",
    "django.contrib.auth.middleware.AuthenticationMiddleware",
    "django.contrib.messages.middleware.MessageMiddleware",
]

2. DEFAULT_AUTO_FIELD (warning при старте на 3.2+)

Если при makemigrations Django пишет WARNINGS: (models.W042) про
AutoField — добавьте в settings.py:

DEFAULT_AUTO_FIELD = "django.db.models.BigAutoField"

В новых проектах (django-admin startproject на 3.2+) эта строка уже есть — не удаляйте.

3. Статика: {% load staticfiles %} → {% load static %}

В старых туториалах встречается:

{% load staticfiles %}
<link rel="stylesheet" href="{% static 'css/style.css' %}">

Пишите:

{% load static %}
<link rel="stylesheet" href="{% static 'css/style.css' %}">

4. PostgreSQL: драйвер psycopg2 → psycopg

Django с 4.2 поддерживает современный драйвер psycopg (версия 3). В новых проектах
часто используют уже его. Отличия в коде нет — только в pip:

pip install psycopg        # современный (Django 4.2+)
# или pip install psycopg2-binary  # старый, тоже работает

Асинхронные view (Django 3.1+)

Из старого текста вы пришли в мир, где Django умеет async def:

# app/views.py
async def home(request):
    return render(request, "app/home.html")

Это работает только на ASGI-сервере (см. раздел «Деплой»). Синхронный стиль
(обычные def) по-прежнему валиден и для большинства сайтов — ничего переписывать
не нужно.

Нюансы, которые ломают код «из 2.x» на практике

  • django.core.urlresolvers удалён → django.urls (reverse, reverse_lazy).
  • django.shortcuts.render_to_response без контекста → лучше render().
  • ugettext_lazy → gettext_lazy, ugettext → gettext.
  • django.utils.encoding.force_text → force_str.

Правило: при встрече ImportError с именем вида django.core.urlresolvers — замените
на django.urls; суффикс _text в именах (например force_text) теперь называется
force_str. Старые пути в примерах времен Django 1.x/2.x почти всегда соответствуют
новому модулю с тем же именем.

Когда писать path() vs re_path() — коротко

Проверка после обновления

python manage.py check                  # структура и настройки
python manage.py makemigrations --check # нет незакоммиченных миграций
python manage.py test                   # упавшие тесты покажут код, требующий правок
python manage.py runserver              # и открой главную — глазами быстрее всего

Порядок действий при переносе старого проекта на новую версию:
1. Поставить последнюю версию Django (актуальную, см. «Документация»).
2. pip install -U django и устранить ImportError (см. таблицу выше).
3. Заменить MIDDLEWARE_CLASSES на MIDDLEWARE, добавить DEFAULT_AUTO_FIELD.
4. Заменить {% load staticfiles %} на {% load static %}, url() на path().
5. manage.py makemigrations --check и manage.py test — зелёное = готово к деплою.

Если после чтения этого списка чувствуете, что «много всего» — на самом деле на небольших
учебных проектах правятся 3–5 строк на проект: маршруты, статические теги и настройки.
Остальная документация туториалов не менялась.

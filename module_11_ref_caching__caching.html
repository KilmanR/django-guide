Кэширование (Cache framework)

Настройка CACHES в settings.py

CACHES = {
    'default': {
        'BACKEND': 'django.core.cache.backends.locmem.LocMemCache',
        'LOCATION': 'unique-snowflake',   # уникальный id для этого кэша
        'TIMEOUT': 300,                   # время жизни в секундах
        'OPTIONS': {
            'MAX_ENTRIES': 1000,          # макс. записей до очистки
            'CULL_FREQUENCY': 3,          # после 1000 удаляем каждую 3-ю
        },
    }
}

Бэкенды (key = 'default' берутся, если не указан AJIAS):
- LocMemCache — в памяти процесса, по умолчанию. Подходит для dev и одного воркера.
- memcached.MemcachedCache / PyMemcacheCache — LOCATION: '127.0.0.1:11211'.
- db.DatabaseCache — LOCATION: 'cache_table' (нужна python manage.py createcachetable).
- filebased.FileBasedCache — LOCATION: '/path/to/dir'.
- Redis — через сторонние пакеты (django-redis) либо встроенный бэкенд в Django ≥ 4:
django.core.cache.backends.redis.RedisCache.

# несколько алиасов, достав по имени:
CACHES['redis'] = {'BACKEND': '...', 'LOCATION': 'redis://127.0.0.1:6379/1'}
from django.core.cache import caches
r = caches['redis']

Низкоуровневый кэш (программный доступ)

from django.core.cache import cache

cache.set('title', 'Привет', timeout=60)   # True/False
cache.get('title', default=None)           # defaults к времени из CACHES
cache.add('key', v, 60)                    # пишет ТОЛЬКО если ключа нет
cache.get_or_set('key', lambda: heavy(), 60)
cache.delete('key')
cache.clear()                              # очистить весь кэш
cache.has_key('key')
cache.set_many({'a': 1, 'b': 2}, 60)
cache.get_many(['a', 'b'])
cache.touch('key', 60)                     # продлить TTL
cache.incr('counter')                      # инкремент числа
cache.decr('counter')

Кэширование всей страницы — cache_page

from django.views.decorators.cache import cache_page

urlpatterns = [
    path('news/', cache_page(60 * 15)(views.news)),   # 15 минут
]

# либо в самом view:
@cache_page(60 * 15)
def news(request):
    ...

Декоратор не кэширует запросы с POST, cookie, сессией и параметрами в URL.

Кэш middleware (весь сайт без форсирования)

MIDDLEWARE = [
    'django.middleware.cache.UpdateCacheMiddleware',    # ПЕРВЫМ
    ...                                                  # остальные
    'django.middleware.cache.FetchFromCacheMiddleware', # ПОСЛЕДНИМ
]
CACHE_MIDDLEWARE_ALIAS = 'default'
CACHE_MIDDLEWARE_SECONDS = 600
CACHE_MIDDLEWARE_KEY_PREFIX = ''   # префикс при общем кэше

Порядок обязателен: update-мидлвер наверху, fetch-мидлвер внизу списка.
Внимание: кэшируются только GET-страницы без параметров строки запроса.

Кэширование фрагментов шаблона

{% load cache %}
{% cache 600 sidebar request.user.username %}
    ... дорого генерируемый фрагмент ...
{% endcache %}
  • первый аргумент — секунды, далее «куски» ключа (можно несколько).
  • при использовании с cookie/сессией не забудьте их в аргументах ключа.

Учёт заголовков (Vary) и версий

from django.views.decorators.vary import vary_on_headers

@vary_on_headers('User-Agent', 'Accept-Language')
@cache_page(60 * 60)
def index(request):
    ...

# версия ключа — просто инвалидировать логически:
cache.set('my_key', v, version=3)
cache.get('my_key', version=3)

Инвалидация после изменения данных

Кэш сам не узнает, что модель изменилась — удаляйте ключи вручную:

from django.core.cache import cache

def save(self, *args, **kwargs):
    super().save(*args, **kwargs)
    cache.delete(f'post:{self.pk}')   # или cache_manager.invalidate

Или храните версию в настройке и инкрементьте её при обновлении данных.

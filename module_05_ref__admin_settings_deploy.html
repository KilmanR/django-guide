Админка (django.contrib.admin)

Регистрация модели

from django.contrib import admin
from .models import Book

@admin.register(Book)          # декомантор
class BookAdmin(admin.ModelAdmin):
    pass

Полезные опции ModelAdmin

class BookAdmin(admin.ModelAdmin):
    list_display = ("title", "author", "price")   # колонки списка
    list_filter = ("author",)                     # фильтры сбоку
    search_fields = ("title",)                    # поле поиска
    list_editable = ("price",)                    # редактирование из списка
    ordering = ("-price",)                        # сортировка
    fields = ("title", "pages")                   # поля в форме
    readonly_fields = ("slug",)                   # только чтение
    prepopulated_fields = {"slug": ("title",)}    # авто-free slug

Inline (связанные в одной форме)

class ChapterInline(admin.TabularInline):
    model = Chapter
    extra = 1

@admin.register(Book)
class BookAdmin(admin.ModelAdmin):
    inlines = [ChapterInline]

Settings — ключевые настройки

# settings.py
SECRET_KEY = "..."            # держите в секрете (env)
DEBUG = True                  # False в проде
ALLOWED_HOSTS = ["example.com"]  # домен/публичный адрес
INSTALLED_APPS = ["django.contrib.admin", "django.contrib.auth", ...]
DATABASES["default"]["ENGINE"] = "django.db.backends.postgresql"
STATIC_URL = "static/"
STATIC_ROOT = BASE_DIR / "staticfiles"
MEDIA_URL = "/media/"
MEDIA_ROOT = BASE_DIR / "media"
LANGUAGE_CODE = "ru-ru"
TIME_ZONE = "Europe/Moscow"   # или ваши

Хранение секретов через переменные окружения

import os
SECRET_KEY = os.environ["DJANGO_SECRET_KEY"]
DEBUG = os.environ.get("DJANGO_DEBUG", "false") == "true"
ALLOWED_HOSTS = os.environ.get("DJANGO_ALLOWED_HOSTS", "").split(",")

Проще всего через .env + python-dotenv, или в Docker-env.

Deploy (публикация)

Миграции и статика (обязательно перед выкатом)

python manage.py migrate
python manage.py collectstatic --noinput

Проверка продакшн-готовности

python manage.py check --deploy

Выведет предупреждения (секреты, DEBUG, allowed_hosts) — устраните их.

Запуск через Gunicorn (WSGI-сервер)

pip install gunicorn
gunicorn mysite.wsgi:application --bind 0.0.0.0:8000 --workers 3

Django + Gunicorn + Nginx + PostgreSQL (типовая связка)

  • Nginx — отдаёт статику/меdia, проксирует / на 8000.
  • Gunicorn — запускает Django (WSGI на 8000).
  • PostgreSQL — база (subtitute на проде вместо sqlite).
  • collectstatic — статика лежит в STATIC_ROOT, её отдаёт Nginx.
  • Миграции применяются до запуска Gunicorn.

Простая автоматизация (как у нас на сервере)

# systemd unit mysite.service
[Unit]
Description=Django app
After=network.target

[Service]
User=www-data
WorkingDirectory=/srv/www/mysite
ExecStart=/srv/www/mysite/venv/bin/gunicorn mysite.wsgi:application --bind 127.0.0.1:8000
EnvironmentFile=/srv/www/mysite/.env
Restart=always

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now mysite

Полезные проверки безопасности (deploy)

  • DEBUG=False всегда в проде.
  • Свой SECRET_KEY (не дефолтный) через env.
  • ALLOWED_HOSTS заполнен доменом.
  • HTTPS через Nginx (certbot / Let's Encrypt).
  • Переменные окружения вместо хардкода паролей/ключей.

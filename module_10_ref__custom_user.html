Custom User Model: свой AbstractUser с первого дня

Официальная рекомендация Django: не используйте стандартного User, если знаете,
что модель пользователя понадобится менять (поле «телефон», «nickname», свой UUID-логин
и т.д.). Делать это нужно в самом начале проекта, до первой миграции: после того как
auth_user уже создан, сменить модель пользователя — очень болезненно.

Почему «до первой миграции»

У Django две главные модели: ваши и встроенная auth.User. Переключить встроенную
модель (через AUTH_USER_MODEL) можно только пока БД не создана — точнее, пока ни одна
миграция auth не применена. Если проект уже запущен и в базе есть auth_user, путь
назад — ручная миграция данных (неприятно, уязвимо).

7 секунд сейчас → 7 часов рефакторинга потом

Как правильно (минимальный вариант)

Шаг 1. Создайте приложение для пользователя сразу

python manage.py startapp users
python manage.py startapp accounts   # или любое имя

Шаг 2. Напишите модель на базе AbstractUser

# users/models.py
from django.contrib.auth.models import AbstractUser
from django.db import models

class User(AbstractUser):
    """Наша модель пользователя: все поля стандартные + добавляем свои."""
    phone = models.CharField(max_length=20, blank=True)
    bio = models.TextField(blank=True)

    def __str__(self):
        return self.username

AbstractUser даёт всё, что было во встроенном User (username, password, groups,
permissions, email, first_name, last_name, is_staff, is_superuser, is_active, date_joined).
Вы просто добавляете свои поля.

Шаг 3. Укажите AUTH_USER_MODEL в настройках

# settings.py
AUTH_USER_MODEL = "users.User"

До makemigrations! Это самая важная строка в проекте с кастомной моделью.

Шаг 4. Формы пользователя

Стандартные UserCreationForm/UserChangeForm работают со встроенной моделью. Для
своей — наследуйте:

# users/forms.py
from django.contrib.auth.forms import UserCreationForm, UserChangeForm
from .models import User

class UserCreationForm(UserCreationForm):
    class Meta:
        model = User
        fields = ("username", "email")

class UserChangeForm(UserChangeForm):
    class Meta:
        model = User
        fields = "__all__"

Шаг 5. Подключите в админке

# users/admin.py
from django.contrib import admin
from django.contrib.auth.admin import UserAdmin
from .models import User
from .forms import UserCreationForm, UserChangeForm

@admin.register(User)
class UserAdmin(UserAdmin):
    add_form = UserCreationForm
    form = UserChangeForm
    model = User

Шаг 6. Регистрация пользователей (вьюхи)

Типичная view для регистрации:

# users/views.py
from django.contrib.auth import authenticate, login
from django.shortcuts import render, redirect
from .forms import UserCreationForm

def signup(request):
    if request.method == "POST":
        form = UserCreationForm(request.POST)
        if form.is_valid():
            user = form.save()
            login(request, user)          # сразу залогинили
            return redirect("home")
    else:
        form = UserCreationForm()
    return render(request, "users/signup.html", {"form": form})

Дальше в любом месте проекта — request.user, и это ваша модель:

def profile(request):
    return render(request, "users/profile.html", {"me": request.user})

Частые ошибки

  • Забыли AUTH_USER_MODEL до миграций. Мигрировали auth → ловите проблему. Если

ещё недалеко — «удалить миграции auth, создать сначала users, потом migrate».
- reverse("...") с settings.AUTH_USER_MODEL вместо User. В ForeignKey(..., null=True)
принято писать settings.AUTH_USER_MODEL, а не класс.
- User.objects.all(), когда вы ждёте свою модель. Используйте settings.AUTH_USER_MODEL
и get_user_model():

from django.contrib.auth import get_user_model
User = get_user_model()          # УЖЕ ваша модель
  • Списали пример из туториала (с прямым User): в моделях замените

ForeignKey(User) на ForeignKey(settings.AUTH_USER_MODEL).

Чек-лист

1. startapp users создан.
2. В users/models.py — class User(AbstractUser) с вашими доп-полями.
3. В settings.py — AUTH_USER_MODEL = "users.User" (до migrate).
4. Свои UserCreationForm/UserChangeForm/UserAdmin.
5. makemigrations users → migrate → всё создалось с нуля.
6. request.user — ваша модель.

Делаете так с первого же проекта — и никогда не попадёте в тупик «модель уже в базе,
а телефон прикрутить надо». Подробности и прод-варианты: официальный раздел
«Customizing authentication» в документации Django.
